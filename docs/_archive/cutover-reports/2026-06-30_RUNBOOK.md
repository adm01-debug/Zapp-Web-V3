## 1. SECURITY - anon read-leak (HIGH / LGPD)

`anon` (public key, **no login**) can read ~350 relations not protected by RLS:
(A) RLS-disabled tables, (B) tables with `USING(true)` anon/public policy,
(C) `security_invoker=off` views bypassing RLS. This exposes the full WhatsApp
message/conversation history, contacts, deals, dashboards, and credential views
(`evolution_instance_credentials`, `n8n_variables`, `v_vault_health`).

`public.evolution_conversations`, `evo.evolution_messages`,
`evo.evolution_conversations`, `public.evolution_instance_credentials`,
`public.n8n_variables`, `public.v_vault_health`,
`public._vault_corrupted_quarantine`, `public._system_health_history`,
`public._system_health_log`, `evo.migration_watermark`
(+ dropped `anon_read` / `anon_read_conversations` policies).

### To finish (closes the remaining ~330)
Run `db/security/2026-06-30_anon_hardening_FULL.sql` in a low-traffic window.
- It **backs up** current anon grants to `archive.anon_grant_backup_20260630`.
- It honours an **ALLOWLIST** (default: `cookies_config`, `workspaces`) - review
  it first; add any relation the logged-OUT app legitimately reads.
- Rollback: `db/security/2026-06-30_anon_hardening_ROLLBACK.sql`.

### Root-cause follow-up (separate task)
The leak exists because the compatibility/dashboard views were created
`security_invoker=off` and granted to anon, and ~34 base tables use
`USING(true)`. REVOKE closes anon now; longer term, recreate those views with
`security_invoker=on` and replace `USING(true)` policies with real scoping
(`auth.uid()` / `workspace_id`) - decide the access model with Pink.

## 2. REALTIME repoint (required for live chat after cutover)

The public names the app subscribes to are **views**; realtime fires on the
**real** source table. Repoint frontend subscriptions:

| App subscribes today | Must subscribe to |
|---|---|
| `public.messages` | `evo.evolution_messages` (filter `deleted_at IS NULL`) |
| `public.conversations` | `evo.evolution_conversations` |
| contatos / agents / calls / campaigns / message_templates | `zapp.*` (same names) |

Notes:
- RLS on the sources is `authenticated USING(true)` -> realtime **delivers** to
  logged-in users. OK.
- The realtime payload carries the **raw** `evo` columns (e.g. `direction='inbound'`,
  `from_me`), NOT the view's computed shape (`direction='incoming'`, `sender`).
  The `onInsert/onUpdate` handler must map raw -> UI shape.
- `evo.evolution_messages` has `REPLICA IDENTITY default`; set FULL if old values
  on UPDATE/DELETE are needed.
