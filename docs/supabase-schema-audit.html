Criticos sao tabelas usadas em fluxos core (inbox, integracoes, webhooks, edge functions) que causam erro 404 visivel ao usuario ou falha silenciosa em edge functions. Medios afetam funcionalidades secundarias (search history, onboarding, stickers pessoais) que provavelmente falham silenciosamente com try/catch.

Recomendacao

Criar uma migration que adicione as 23 tabelas/views ausentes. Para os 6 casos de nomes divergentes, a abordagem mais segura e criar uma VIEW alias (ex: CREATE VIEW zapp.evolution_instances AS SELECT * FROM zapp.evolution_instances_public) para evitar alterar o codigo existente e preservar compatibilidade. As 17 tabelas restantes precisam ser criadas como BASE TABLE com as colunas inferidas do uso no codigo.
